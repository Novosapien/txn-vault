The bet, and why timing decides it

TXN's differentiation is not feature parity with Marqeta or Galileo. It is being agentic-native where they are retrofitted. That is a structural advantage an incumbent cannot copy quickly: they cannot redesign a console built for expert users into an agent-first product without disrupting the customers they already have.

The incumbent model

  • API-first but operationally heavy: clients still need card experts to configure and run programs.
  • 50 to 60 configuration properties exposed raw, with no business-language wrapper. People turn them on and off and break things.
  • AI bolted onto a console designed for experts. A side panel, not the interface.

The agentic-native model

  • The user does not become a card expert. The agent is the card expert.
  • Onboarding collapses from a multi-week exercise into a guided conversation.
  • The agent is the primary interface from day one, with a human in the loop until trust is earned.
I want to know as little as possible about the details of card programs. I don't want to employ a card expert. I want you to be my card expert. Ian Johnson, CEO, TXN

The agentic stack that makes this buildable, MCP, A2A, dependable tool-use, multi-step reasoning, reached production-readiness only recently. A small lead in agentic maturity converts into a structural product advantage during this window. The cost of waiting is concrete: ship Concept 1 alone and the product can feel a year behind on launch day.

The plan is built around that risk. The pilot demonstrates the agentic experience in six weeks, independent of the other vendors' timelines, so TXN can show the market its difference now rather than after the platform plumbing is finished.

How we deliver, and how we de-risk it

Every component graduates along the same trust ladder, mapped to TXN's three concepts. A human stays in the loop until the agent has earned autonomy, and the platform's approval queues are respected at every step.

CONCEPT 1
Co-pilot
The user drives. The agent recommends and explains impact before anything changes. Human-initiated, human-validated.
CONCEPT 2
Agent-advisor
The agent initiates: "I have noticed this, here is the plan, may I execute?" The named approver signs off. Agent-initiated, human-validated.
CONCEPT 3
Full agentic / A2A
The client's own agent talks to TXN's agent through MCP and A2A, with the same permissions and approvals as the human it represents.

Map, Train, Deploy, Scale

Map
Lock the work each component owns, its tools, permissions, and the approval gates it must respect. Largely delivered in Sprint Zero.
Train
Ground each agent in TXN's documentation and the live API contract, then harden against the failure modes that matter in payments.
Deploy
Ship behind feature flags and a kill switch, starting human-validated, with full audit on every agent action.
Scale
Earn autonomy component by component as the data flywheel fills and confidence is evidenced in production.
Governance is built in, not bolted on. Permission scoping mirrors the Console, high-blast-radius changes route through the existing two-person approval queue, every agent action is logged to an append-only audit trail (immutable by design; storage being finalised with DT), and model-tier routing plus caching and budget thresholds keep consumption bounded by design.

Phase 1: the six-week agentic pilot

The pilot exists to prove the experience that TXN is betting on, before the other vendors' surfaces are ready. It runs on simulated tools and synthetic data, so almost nothing in it waits on Direct Transact or Stackworkz.

What we build

  • A working Full Agentic Experience showcase: a Claude-like interface that takes a goal, plans, renders live UI in the conversation, and acts on approval.
  • The Agent Access Layer foundations: the MCP tool surface and permission model, running against mocked Core API endpoints built from the YAML and sample payloads.
  • Internal Ops v1: the customer-onboarding agent, meeting capture, and the knowledge engine, the low-dependency, CRM-based parts that return value from day one.

Why pilot-first

  • It demonstrates Concept 2 and Concept 3 now, answering the "someone will beat us to it" risk head-on.
  • It de-risks the hardest component (the XL Full Agentic Experience) on simulation before a penny of wire-in spend.
  • It surfaces gaps in the API contract and the data the agent needs, feeding the wire-in phase.
  • Internal Ops v1 needs no DT or Console dependency, so it banks value while the platform stabilises.
Outcome of Phase 1. A demonstrable agentic experience TXN can show to its market and its board, plus a hardened foundation (tool surface, permission model, simulation harness) that the rest of the build plugs into.

Phase 2: what we deliver to launch

Phase 2 wires the agentic layer into production through the four months to the October launch, set out component by component. Each is built synthetic-first: against mock APIs and data, with the demo-data flags dropping as the real surfaces land, so nothing stalls waiting on the platform. This page covers the launch-critical layer; the next covers the Developer Portal and Internal Ops.

Agent Access Layer L the foundation every agent rides on

  • A single MCP tool surface that wraps the Core API as business-language tools (issue or suspend a card, configure a product, query transactions), gated per user, permission, and turn.
  • A permission model that mirrors the Console's granular roles, plus an AI-specific permission config, with approvals routed into the existing Console approval queue under the two-person rule.
  • A combined audit trail across Console, Core API, and AI chat, so every agent action is attributable and reconstructable.
  • The A2A endpoint: an inbound door for a client's own external agent, reusing the same tools, scoping, approval, and audit.

Full Agentic Experience XL the showcase, agent as the interface

  • A Claude-like surface: state a goal in natural language, the agent plans, renders live interface inside the conversation, and acts only on approval.
  • Generative UI: the agent calls a tool and the front end renders the matching component from the Console library, live and clickable, deep-linking back into the Console.
  • Multi-agent planning that composes across journeys (for example, "change a transaction limit and show me the impact"), runs steps concurrently, and executes in order on approval.
  • Saved, revisitable views and scheduled tasks, proven on roughly 100-run guard-rail simulations, then wired onto the live Core API so the full experience runs in production before mid-October.

Co-pilot v1 M reactive in-Console assistant

  • Natural-language Q&A and navigation, page-scoped with page context and guard rails.
  • Guided configuration that collapses 100+ product-config fields into a confirm-not-configure conversation, surfacing what most clients in a given pattern do.
  • Action on confirmation: plan-then-act for multi-step flows via the Access Layer, with explicit button confirmation and bundled approvals.
